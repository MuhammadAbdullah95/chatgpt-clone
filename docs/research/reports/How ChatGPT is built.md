# Ordinary Web Tools Power ChatGPT at Scale

ChatGPT is a fairly ordinary web app sitting on top of an extraordinary GPU fleet. The website is a **React and TypeScript** app [Confirmed] that outside teardowns show running on **React Router 7, Vite, Tailwind CSS, Radix UI and TanStack Query** [Reported], and the backend is **mostly Python with FastAPI** on asyncio [Confirmed for Python; Reported for FastAPI], with **Go** now running the real-time voice server [Confirmed]. Answers reach the browser as **server-sent events over a single POST request**, sent as small "patch" updates [Reported], and each conversation is stored as a **tree of messages** so that edits and regenerations become branches [Reported]. The core database is **one PostgreSQL primary with about 50 read replicas**, with newer write-heavy data moved to **Azure Cosmos DB** and user data cached in **Redis** [Confirmed]. Login runs through **auth.openai.com** (email, Google, Microsoft or Apple) [Confirmed], while a separate anti-bot system called **Sentinel** checks every message [Reported]. All of this runs on **hundreds of Kubernetes clusters** across Azure, AWS, Oracle and other clouds [Confirmed], and OpenAI's own outage reports show that the worst failures come from config changes, login and shared systems, not from GPUs. For a clone, the good news is that most of ChatGPT's hard problems come from running its own models for 800 million people; a small team calling a hosted model API can copy the app-layer design without inheriting them. One warning applies throughout: OpenAI has never published an architecture overview of chatgpt.com, so most web and API details come from outside inspection and can change without notice.

_How to read the tags: **[Confirmed]** = OpenAI said it officially (blog, help center, API docs, status-page write-up or job posting). **[Reported]** = a credible third party found or reported it (tech press, a partner, a reverse-engineering write-up, user reports). **[Inferred]** = our own reasoning from indirect evidence. Facts are as of 22 November 2026._

## The website is a React app built around a ready-to-type input box

OpenAI has never written an engineering post about the chatgpt.com web stack. The only official clue is its job postings, which ask for "strong experience with modern frontend stacks such as **React and TypeScript**" and never name a framework, CSS library or build tool [Confirmed] ([OpenAI Careers](https://openai.com/careers/frontend-software-engineer-chatgpt-space-san-francisco/)). Almost everything else comes from one detailed teardown published on 2 July 2026 by Dennis Brotzky, who studied the page's HTML, JavaScript and network traffic without access to the source code ([performance.dev](https://performance.dev/chatgpt)). That teardown traces three eras [Reported]. ChatGPT launched on 30 November 2022 on **Next.js 12**. Around August–September 2024 it switched to **Remix with the Vite build tool**. When Remix merged into **React Router v7** in November 2024, ChatGPT followed. As of July 2026 the page runs **React 19** with **streaming server-side rendering**: the server sends the basic page first and fills in parts as data arrives ([performance.dev](https://performance.dev/chatgpt)). The same codebase holds **354 routes, of which only about 13 are the chat app**; the rest are marketing pages. OpenAI never announced either migration or explained why. The popular explanations (ChatGPT is mostly a client-side app where search ranking matters little, and Vite builds were faster) are outsider opinion [Reported] ([DEV Community](https://dev.to/asif_1122se/openais-transition-from-nextjs-to-remix-a-strategic-move-in-web-development-5029)).

The same teardown names the main libraries [Reported] ([performance.dev](https://performance.dev/chatgpt)). Styling is **Tailwind CSS v4** on top of named color variables ("tokens" such as `bg-token-main-surface-primary`), so light mode, dark mode and chat themes simply swap variable values. A tiny script in the page head reads the saved theme before anything is drawn, so there is no flash of the wrong theme. **Radix UI** supplies menus, popovers, selects and toasts. The message input box (the "composer") is a **ProseMirror** rich-text editor, code blocks use **CodeMirror 6**, and math uses **KaTeX** plus a hidden MathML copy for screen readers. Server data such as conversations and history is managed by **TanStack Query**, whose cache is pre-filled by the server. Feature flags come from **Statsig** (the July 2026 page carried 556 feature gates, 144 dynamic configs and 192 experiment layers), real-user monitoring from **Datadog**, maps from Mapbox GL, and voice from LiveKit/WebRTC. The UI uses the computer's system font rather than a downloaded web font. Two gaps remain: no public source names the **markdown parser** or any **client-state library** (such as Redux or Zustand).

The clearest design lesson is that the whole page starts up around one goal: **making the input box usable as fast as possible** [Reported]. A loading flag literally named `deferStartupImportsUntilComposerTTFI` holds back other startup code until the composer is ready. Only 14 critical files are preloaded. The code-block view, the reasoning ("chain of thought") view and the KaTeX math fonts load only when an answer actually needs them. Static files come from `chatgpt.com/cdn/assets` with 30-day caching and no service worker ([performance.dev](https://performance.dev/chatgpt)). The weak spot is long chats: the message list is **not virtualized**, so every message stays in the page [Reported] ([performance.dev](https://performance.dev/chatgpt)), and users report freezes "exacerbated by long chat histories" [Reported] ([OpenAI Community](https://community.openai.com/t/intermittent-ui-freeze-hangs-across-web-windows-and-android-clients-exacerbated-by-long-chat-histories-and-session-reloads/1355269)).

The chat app has two main screens [Reported] ([performance.dev](https://performance.dev/chatgpt)): a new chat at **`/`** and an existing chat at **`/c/<conversation-id>`**, both inside one shared layout that holds the sidebar and the composer. Logged-out visitors can chat at `/` without signing in, through separate `/backend-anon/*` endpoints, and each anonymous visitor gets a real user ID so that rate limits and experiments still work. [Inferred] When a new chat starts, the server assigns the conversation ID early in the stream, the client swaps the URL to `/c/<id>` without reloading the page, and the new chat appears at the top of the sidebar. Because the shared layout wraps both screens, only the message area changes when the user moves between chats.

Outside the browser, the apps take a different path. The **iOS app is native Swift** (UIKit and SwiftUI) and the **Android app is native Kotlin with Jetpack Compose**, each built on a shared mobile platform that also powers Sora and other OpenAI apps [Confirmed] ([OpenAI Careers, iOS](https://openai.com/careers/ios-engineer-chatgpt-mobile-infrastructure-san-francisco/); [OpenAI Careers, Android](https://openai.com/careers/android-engineer-chatgpt-library-team-seattle/)). On 9 July 2026 OpenAI launched a **new desktop app for macOS and Windows** that combines Chat, Work and Codex, and renamed the old Mac app "ChatGPT Classic" [Confirmed] ([OpenAI macOS release notes](https://help.openai.com/sr-rs/articles/9703738-chatgpt-macos-app-release-notes)). The new app is the Codex app updated in place [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/20001276-moving-to-the-new-chatgpt-desktop-app)), and the Codex app is reported to be built with **Electron** [Reported] ([Simon Willison](https://simonwillison.net/2026/Feb/2/introducing-the-codex-app/)). So the new desktop app is very likely Electron too [Inferred], a shift away from the native Classic Mac app [Reported] ([Allen Pike](https://allenpike.com/2025/why-is-chatgpt-so-good-claude)).

## Python and FastAPI run most of the backend, and Go now runs voice

The firmest evidence about the backend comes from OpenAI's own March 2023 outage report: "We use the redis-py library to interface with Redis from our **Python server, which runs with Asyncio**" [Confirmed] ([OpenAI](https://openai.com/index/march-20-chatgpt-outage/)). Asyncio is Python's built-in way of handling many waiting connections at once. In a 2025 interview, ChatGPT's head of engineering and OpenAI's VP of engineering described the stack as "**mostly Python and FastAPI**", with "some C" for speed-critical code and **Temporal** as a workflow engine that keeps multi-step jobs reliable when single steps fail [Reported] ([Simon Willison](https://simonwillison.net/2025/May/13/launching-chatgpt-images/); [The Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/chatgpt-images)). During the March 2025 image-generation launch, the team added an **asynchronous queue** to hold back free-user load [Reported] ([Simon Willison](https://simonwillison.net/2025/May/13/launching-chatgpt-images/)). Job postings agree: one backend role lists Python, FastAPI and Postgres [Confirmed] ([OpenAI Careers](https://openai.com/careers/backend-software-engineer-%28evals%29-san-francisco/)), and a ChatGPT Engineering listing asks for "Go, Python, Rust, C++" [Confirmed] ([Built In](https://builtin.com/job/backend-software-engineer-chatgpt-engineering/8383312)).

The one place where another language is officially confirmed in ChatGPT's live path is voice. OpenAI's 3 August 2026 engineering post on its GPT-Live voice system says the **media server and inference logic were rewritten in Go, replacing a Python asyncio version**, and that the new system's 95th-percentile frame delivery now matches the old system's median [Confirmed] ([OpenAI](https://openai.com/index/continuous-voice-interaction-with-gpt-live/)). The pattern is telling [Inferred]: Python works well where a request mostly waits on the model and streams text, but OpenAI moved to a compiled language where the timing of every audio frame matters.

All OpenAI services, ChatGPT included, run on **Kubernetes**, spread over "hundreds of Kubernetes clusters globally" [Confirmed] ([OpenAI Status](https://status.openai.com/incidents/ctrsv3lwd797/write-up)). A ChatGPT Infrastructure job posting lists the team's daily concerns as "caching, consistency, queueing/backpressure" and "rate limiting, load shedding, dependency isolation" [Confirmed] ([OpenAI Careers](https://openai.com/careers/software-engineer-chatgpt-infrastructure-san-francisco/)). Several basics remain unknown: whether the backend is one large service or many small ones, which ORM writes the database queries (OpenAI mentions "ORM-generated SQL" without naming it), and what the API gateway looks like.

## Answers stream as small patches over one long POST response

When you send a message, the browser makes a **POST request** and the server keeps the response open, pushing text in the **server-sent events (SSE)** format (`text/event-stream`), a simple standard for sending a stream of small messages over one HTTP response [Reported]. ChatGPT does not use the browser's built-in `EventSource` tool, which can only make GET requests; it reads the response body directly with `fetch()` and a stream reader ([Abdeltwab](https://ahmed-n-abdeltwab.github.io/blog/2025/08/25/chatgpt-sse-architecture.html)). The endpoint moved from `/backend-api/conversation` (2023–2025) to **`/backend-api/f/conversation`** (2026) [Reported] ([GitHub issue](https://github.com/Ma-XX-oN/AgentPanelSpeaker.NET/issues/115)), and logged-out users hit `/backend-anon/f/conversation` [Reported] ([performance.dev](https://performance.dev/chatgpt)). Chat text does not use WebSockets [Reported] ([performance.dev](https://performance.dev/chatgpt)).

The stream format has changed over time. In 2023 every event carried **the full answer so far**, and clients worked out the new part themselves [Reported] ([hideaway blog](https://hideaway-7r8.pages.dev/en/posts/2023/03/chatgpt-web-to-api/)). By 2026 the stream uses **`delta_encoding: "v1"`**: an "append" operation on `/message/content/parts/0`, followed by short `{"v":"..."}` events that each add the next piece of text. Open-source clients parse operations named add, append, replace, remove and patch [Reported] ([GitHub issue](https://github.com/Ma-XX-oN/AgentPanelSpeaker.NET/issues/115); [GitHub issue](https://github.com/WLV-ZEDD/dsh-chatgpt-web/issues/11)). Messages also carry a `channel` ("commentary" or "final") and a `recipient`, which suggests that tool calls and reasoning travel in the same stream as the answer [Reported]. A November 2026 capture shows the request body holding `action`, `messages`, `parent_message_id`, `model`, `conversation_mode`, `supported_encodings: ["v1"]` and `timezone` [Reported] ([GitHub issue](https://github.com/i098/codex-gpui/issues/1528)). [Inferred] The switch from full text to patches makes sense: resending the whole answer every time costs more and more as the answer grows, while patches stay small and can also update status, metadata and tool calls.

On screen, the client **re-parses and re-renders the growing message** on every update and has to cope with half-finished markdown, such as an unclosed code block or a half-built table [Reported] ([performance.dev](https://performance.dev/chatgpt)). A Stop button exists and has drawn reliability complaints [Reported] ([OpenAI Community](https://community.openai.com/t/restore-chatgpts-stop-button-without-errors/1132068)). Copy and feedback buttons appear only once the stream ends [Reported] ([OpenAI Community](https://community.openai.com/t/chatgpt-web-gets-stuck-in-generating-state-after-long-gpt-5-6-sol-responses-finish/1393624)), and the UI has scroll lock and per-message version switching [Reported] ([OpenAI Community](https://community.openai.com/t/several-bugs-after-recent-updates-response-couldnt-load-prompt-version-switching-missing-scroll-lock-temporary-chat/1403908)). If you refresh mid-answer, the answer keeps generating on the server and you cannot send a new prompt until it finishes [Reported] ([OpenAI Community](https://community.openai.com/t/restore-chatgpts-stop-button-without-errors/1132068?page=2)), and users sometimes see a "**Resume stream unavailable**" error [Reported] ([SmartScope](https://smartscope.blog/en/blog/chatgpt-resume-stream-unavailable-2026/)). [Inferred] Together these show that generation runs separately from the browser connection and that the client can reattach to it, though no public source shows exactly how.

OpenAI's public API documents the same pattern officially, and it is the best blueprint available. It streams **typed SSE events** such as `response.created`, `response.output_text.delta`, `response.completed` and `error` [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/streaming-responses)). Its "background mode" lets a client **resume a dropped stream** by passing the last event's `sequence_number` as `starting_after`, and cancel a run with `POST /v1/responses/{id}/cancel` [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/background)). Moderation scores arrive only after the full output, not mid-stream [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/streaming-responses)), and a `response.compaction.compacting` event shows the API can shrink long contexts on the server [Confirmed] ([OpenAI API reference](https://developers.openai.com/api/reference/resources/responses/streaming-events)).

## Every chat is a tree, stored on one giant Postgres plus a sharded store

ChatGPT does not store a conversation as a simple list. The official data export (`conversations.json`, now split into numbered files) gives each conversation a **`mapping` of message nodes**. Each node has an `id`, a `parent`, a list of `children` and a `message`, and a **`current_node`** field points to the message the user is looking at [Reported] ([chatgpt-to-markdown docs](https://difegam.github.io/chatgpt-to-markdown/reference/data-models)). Editing a message or regenerating an answer adds a **sibling branch** instead of overwriting anything, and the visible thread is rebuilt by walking from `current_node` back up to the root [Reported] ([Level Up Coding](https://levelup.gitconnected.com/your-chatgpt-history-is-a-tree-not-a-transcript-2026-5660ceb301d4)). Live requests send a `parent_message_id`, which ties each new turn to a specific node [Reported] ([GitHub issue](https://github.com/i098/codex-gpui/issues/1528)). Messages carry an author role (system, user, assistant or tool), a `content_type` (such as text, multimodal_text, code, thoughts, reasoning_recap or execution_output), a status and metadata. Images appear as **pointers** with width, height and size rather than as raw bytes [Reported] ([chatgpt-to-markdown docs](https://difegam.github.io/chatgpt-to-markdown/reference/data-models)). OpenAI has never published a formal spec of this format. The "Branch in new chat" feature (September 2025) builds directly on the tree [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)).

The database is the best-documented part of ChatGPT. In a 22 January 2026 post, OpenAI said ChatGPT's core relational store is **one unsharded Azure Database for PostgreSQL primary with nearly 50 read replicas** across several regions, serving **millions of queries per second for 800 million users**, with low double-digit millisecond p99 latency and **five-nines availability** [Confirmed] ([OpenAI](https://openai.com/index/scaling-postgresql/)). Load grew more than tenfold in one year. To survive, OpenAI sends reads to replicas, pools connections with **PgBouncer** on Kubernetes (cutting connection time from 50 ms to 5 ms), and puts a **cache with a lock/lease** in front so that only one request refills a missing key. It also avoids big multi-table joins (one 12-table join had caused past incidents), kills idle transactions, splits high- and low-priority traffic, caps schema changes at a 5-second timeout, and rate-limits at the app, pooler, proxy and query layers [Confirmed] ([OpenAI](https://openai.com/index/scaling-postgresql/)). Writes are the limit. Shardable, write-heavy workloads moved to **Azure Cosmos DB**, and **no new tables are added to Postgres** [Confirmed]. The only top-severity database incident in 12 months came during the image-generation launch, when writes jumped more than tenfold as over 100 million users signed up in a week [Confirmed]. A Cosmos DB failure caused a ChatGPT outage on 23 January 2025 [Confirmed] ([OpenAI Status](https://status.openai.com/incidents/01JMYB40J9DVR9D13RJN1W5SWV)), so it is already in the critical path. OpenAI has not said which ChatGPT data lives in which store; [Inferred] high-volume per-user data such as messages is the likeliest candidate for Cosmos DB.

**Redis Cluster** caches user information so the server does not hit the database on every request [Confirmed] ([OpenAI](https://openai.com/index/march-20-chatgpt-outage/)). That cache was at the heart of the March 2023 incident, when a bug in the Python Redis client let some users see **other users' chat titles** in their sidebar. The fix added checks that cached data belongs to the user asking for it [Confirmed] ([OpenAI](https://openai.com/index/march-20-chatgpt-outage/)). The lesson for any clone is concrete: every cache entry must be keyed by user and checked for ownership.

Uploaded files appear to live in **Azure Blob Storage**. One reverse-engineered client shows a three-step upload: the client registers the file and gets back an upload URL pointing to Azure Blob, sends the bytes straight to that URL, then asks the backend to process the file. The message then refers to the file as `file-service://{file_id}` [Reported, one third-party implementation] ([DeepWiki](https://deepwiki.com/realasfngl/ChatGPT/8.4-image-upload-and-multimodal-support)). OpenAI has never named its file store. Officially, storage is capped at **25 GB per user and 100 GB per organization** [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8555545-file-uploads-faq)), although a May 2026 release note listed different per-plan Library caps (from 500 MB on Free to 100 GB on Pro), so the two numbers may measure different things [Confirmed, conflicting] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). Deleted chats are permanently removed from OpenAI systems within 30 days, with stated exceptions [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8809935-how-to-delete-and-manage-your-chatgpt-history-and-data)). Saved memories are stored separately from chats [Confirmed] ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)). Data export is a background job that produces a ZIP of JSON files plus an HTML viewer; it can take up to 7 days, and the download link expires after 24 hours [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/7260999-how-do-i-export-my-chatgpt-history-and-data)).

Long conversations are the least documented area. OpenAI publishes context-window sizes per plan, and they change with each model. An early-2026 version listed 16K tokens for Free, 32K for Plus and 128K for Pro on the fast model [Confirmed, since superseded] ([OpenAI Help, older version](https://help-lb.openai.com/en/articles/11909943-gpt-55-in-chatgpt)), and manually selected Thinking models reached 256K in February 2026 [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). But OpenAI does not explain how ChatGPT trims a chat that grows too long. A December 2025 reverse-engineering study found that **the oldest messages in the current chat are dropped first** when space runs short [Reported] ([LLMrefs](https://llmrefs.com/blog/reverse-engineering-chatgpt-memory)). [Inferred] Given the API's compaction event, summarizing older turns is also plausible.

## The sidebar pages through chats 28 at a time, newest first

The history sidebar is filled by a private list endpoint, **`GET /backend-api/conversations?offset=0&limit=28&order=updated…`**, which returns chats in pages of 28, sorted by last update. One user's trace showed requests at offsets 0, 28, 56, 84 and 112 [Reported] ([OpenAI Community](https://community.openai.com/t/chatgpt-web-conversation-history-returns-persistent-429-rate-limit-and-fails-to-load/1391615)). The page size has changed over time, from a maximum of 100 in 2023 [Reported] ([0xdevalias gist](https://gist.github.com/0xdevalias/4e54bb28a02db5357ea4fa3a872fc5fc)) to 20 in 2025 [Reported] ([Abdeltwab](https://ahmed-n-abdeltwab.github.io/blog/2025/08/25/chatgpt-sse-architecture.html)) to 28 in 2026. The server-rendered page tells the client to **prefetch history and starred chats** on load (`shouldPrefetchHistory`, `shouldPrefetchStarredConversations`) [Reported] ([performance.dev](https://performance.dev/chatgpt)). Offset paging has visible costs in user reports: a new tab often needs two back-to-back loads, deleting one chat re-fetched offsets 0, 28 and 56, and heavy users hit persistent **429 "too many requests"** errors [Reported] ([OpenAI Community](https://community.openai.com/t/chatgpt-web-conversation-history-returns-persistent-429-rate-limit-and-fails-to-load/1391615)). One writer also found that the reported `total` count can be too low [Reported, single source] ([Level Up Coding](https://levelup.gitconnected.com/chatgpts-api-listed-775-of-10-500-chats-and-said-that-was-all-c7382bab2cbf)).

Chat titles are **generated automatically by a separate model call**, through an internal route reported as `gen_title` [Reported] ([scrapbox](https://scrapbox.io/takker/chatGPT_backend_API)). Users describe titles as created once from the first message and never refreshed, and they can rename chats by hand [Reported] ([OpenAI Community](https://community.openai.com/t/let-chat-titles-update-as-the-conversation-evolves/1394299)). A 2026 bug that produced "random Chinese spam-like" titles points to a generative model rather than simple cutting of the user's text [Reported] ([OpenAI Community](https://community.openai.com/t/random-chinese-spam-like-text-appearing-as-automatically-generated-chatgpt-chat-titles/1392443)). Titles are saved on the conversation record [Reported] ([chatgpt-to-markdown docs](https://difegam.github.io/chatgpt-to-markdown/reference/data-models)), and the 2023 leak confirms that the sidebar list is a per-user list served through the Redis-cached server path [Confirmed] ([OpenAI](https://openai.com/index/march-20-chatgpt-outage/)).

The way the list is organized keeps changing. Users reported in June 2025 that the "**Today**" and "**Yesterday**" headings were removed, leaving one flat list [Reported] ([OpenAI Community](https://community.openai.com/t/please-bring-back-the-chronological-sidebar-grouping/1280889)), though one add-on vendor still describes date groups [Reported, conflicting] ([NorthLab](https://northlabapps.com/blog/chatgpt-conversation-dates/)). **Pinned chats** arrived in December 2025, and search across chats, projects and files was upgraded in July 2026 [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). **Archiving** hides a chat from the sidebar without deleting it, archived chats stay searchable under Settings → Data controls, and bulk "archive all" and "delete all" also cover chats inside projects [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8809935-how-to-delete-and-manage-your-chatgpt-history-and-data)). [Inferred] On the client this behaves like an infinite-scroll list over pages, where a deleted chat disappears at once and the loaded pages are then re-fetched. Date headings are just a client-side grouping by update time. Paging with a cursor based on (user, last update, chat id) would avoid the repeated re-fetches users see with offsets.

## Sign-in proves who you are, and Sentinel checks that you are human

ChatGPT accepts **email and password, or Google, Microsoft or Apple** sign-in. An account stays tied to the method used at sign-up, and SMS is not an alternative login [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/4936824-can-i-change-my-authentication-method); [OpenAI Help](https://help.openai.com/en/articles/7426629-why-cant-i-log-in-to-chatgpt)). The identity server is **`auth.openai.com`**. Since September 2026 it also acts as a standard OAuth 2.0 / OpenID Connect provider for "Sign in with ChatGPT", using the Authorization Code flow with PKCE and the scopes `openid`, `profile` and `email`; partner apps receive name, email and picture, but no conversations or memory [Reported, citing OpenAI docs] ([MIXED News](https://mixed-news.com/en/?p=35164)). The login domain was historically fronted by **Auth0**, judging by users who fixed login errors by switching to `auth0.openai.com` [Reported] ([Mozilla Support](https://support.mozilla.org/id/questions/1469068)). Whether that is still true in 2026 is unknown. Since October 2026 the mobile apps allow two signed-in accounts, each with its own memory and settings [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)).

Session handling is reported, not documented. The web client keeps a **long-lived refresh token in a cookie** and sends a **short-lived Bearer access token** with each backend call; an expired token produces 403 errors [Reported] ([Abdeltwab](https://ahmed-n-abdeltwab.github.io/blog/2025/08/25/chatgpt-sse-architecture.html)). Cookie names, token lifetimes and passkey support are not public.

Login is only the first gate. Before each chat POST, the client calls `POST /sentinel/chat-requirements/prepare` and then sends a prepare token plus a **proof-of-work** token in the request headers [Reported] ([GitHub issue](https://github.com/i098/codex-gpui/issues/1528)). This "Sentinel" code runs in a sandboxed iframe [Reported] ([performance.dev](https://performance.dev/chatgpt)). An independent study of 377 requests from 32 users found that **every message triggers a Cloudflare Turnstile check** of 55 browser, network-edge and app-state properties, including whether the React app has fully loaded. It runs alongside behavioral signals such as keystroke timing and mouse speed. The proof-of-work was solved in under 5 ms 72% of the time, so it is not the main defense [Reported] ([GIGAZINE](https://gigazine.net/gsc_news/en/20260502-chatgpt-cloudflare/)). OpenAI's help pages say ChatGPT uses CAPTCHAs against bots [Confirmed, via secondary quote] ([Penligent](https://www.penligent.ai/hackinglabs/chatgpt-and-cloudflare-turnstile-what-the-react-state-analysis-actually-shows/)). The edge network in front of the website is almost certainly **Cloudflare**. On 18 November 2025 OpenAI blamed "an upstream third-party networking provider" for an outage that took down web login while the mobile apps and the API kept working [Confirmed] ([OpenAI Status](https://status.openai.com/incidents/01KABE2437NJYKBFHT22SD3H92/write-up)). The timing matched Cloudflare's own bot-management outage that day [Confirmed] ([Cloudflare](https://blog.cloudflare.com/18-november-2025-outage/)), and ChatGPT users saw "Please unblock challenges.cloudflare.com" [Reported] ([Fox Business](https://www.foxbusiness.com/technology/cloudflare-chatgpt-x-among-sites-affected-global-network-issues)). [Inferred, high confidence] The unnamed provider was Cloudflare.

Usage limits sit on top. As of November 2026, Free and Go users have "**unlimited everyday text chats, subject to abuse-prevention safeguards**", with separate limits for uploads, image generation, voice and data analysis. Thinking models have per-plan limits; when a limit is hit, "ChatGPT may continue with another available model" and shows the reset time [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/11909943-gpt-6-in-chatgpt)). Hidden "mini" fallback models take over after limits and never appear in the model picker [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). Server-side rate limiting is layered across the app, the connection pooler, the proxy and the query layer [Confirmed] ([OpenAI](https://openai.com/index/scaling-postgresql/)). Login is also a recurring weak point: OpenAI's status write-ups name login or auth services in at least four incidents between November 2025 and July 2026 [Inferred from Confirmed write-ups], and in February 2026 failed logins caused clients to retry so often that the retries made the outage worse [Confirmed] ([OpenAI Status](https://status.openai.com/incidents/01KGJK9Q6PDB3C3VX6MPCY6106/write-up)).

## Images and files upload first, then travel with the message as pointers

**Every ChatGPT model accepts images**: PNG, JPEG or non-animated GIF, up to **20 MB each**, with no fixed number per message. Images "are resized before analysis", and the model ignores file names and metadata [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8400551-chatgpt-image-inputs-faq)). Since February 2026 a single message can carry **20 files** [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). Image understanding first arrived on 25 September 2023 [Confirmed] ([OpenAI](https://openai.com/index/chatgpt-can-now-see-hear-and-speak/)), and GPT-4o made text, vision and audio one model in May 2024 [Confirmed] ([OpenAI](https://openai.com/index/hello-gpt-4o/)). Inside ChatGPT an image follows the upload-then-pointer flow described in the storage section [Reported]. The public API equivalent is an `input_image` part that takes a URL, base64 data or an uploaded file ID, plus a `detail` level. Newer models charge for images by 32-pixel patches, so a 1024×1024 image costs about 1,229 tokens on `gpt-6-astra` at high detail [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/images-vision)). OpenAI does not say which detail level ChatGPT itself uses.

Documents follow the same path with different limits [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8555545-file-uploads-faq)): documents up to **512 MB and 2 million tokens per file**, spreadsheets around 50 MB, audio up to 512 MB on paid plans only, and an upload rate of **80 files every 3 hours (Free: 3 per day)**. PDFs attached to a chat are read for both text and images, but project and GPT knowledge files "may not include embedded images automatically". Spreadsheets and heavy analysis go to **Data Analysis**, a stateful Python (Jupyter) sandbox that "cannot make external web requests" [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8437071-data-analysis-with-chatgpt)). Since June 2026, pastes longer than 10,000 characters turn into attachments automatically [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). The public API shows the likely split: PDFs reach the model as extracted text plus page images, other documents as text only, and spreadsheets are parsed up to the first 1,000 rows per sheet [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/pdf-files)). [Inferred] ChatGPT seems to handle a file in one of three ways: put its text straight into the prompt, search inside it when it is too big (as with project files), or hand it to the Python sandbox.

Image generation happens inline in the chat. ChatGPT used DALL·E 3 until **25 March 2025**, when GPT-4o's native image generation took over. Images could take "up to one minute", and all carry **C2PA** metadata that marks them as AI-made [Confirmed] ([OpenAI](https://openai.com/index/introducing-4o-image-generation/)). Demand was so high that Sam Altman wrote "our GPUs are melting" and added temporary rate limits [Confirmed, via quote] ([Fortune](https://fortune.com/2025/03/28/sam-altman-chatgpt-gpus-melting-ai-images/)). OpenAI has since shipped **Images 2.0** on 21 April 2026 [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)), reported to use the `gpt-image-2` model [Reported] ([eWeek](https://www.eweek.com/news/openai-chatgpt-images-2-0/)); **Images 2.5** on 8 September 2026, with up to 50% lower latency, comments placed directly on images, a Sketch tool, and **more than 3 billion images a week** across ChatGPT and the API [Confirmed] ([OpenAI](https://openai.com/index/introducing-chatgpt-images-2-5/)); and **Images 2.6** on 4 November 2026 [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). [Inferred] In the chat flow, image generation behaves like a tool that the chat model calls, with a placeholder shown while the slow job runs.

### Voice went from a three-model relay to one model that listens while it talks

ChatGPT has two separate voice features. **Dictation** is the microphone in the composer: the recording is sent for transcription and comes back as text you can edit before sending [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/12168547-voice-dictation-faq)). On 18 November 2026, **Live Dictation** began showing text as you speak and removed the old 10-minute recording limit [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). OpenAI does not name the model behind dictation. Voice and Dictation together have **more than 150 million users** [Reported, quoting OpenAI] ([TechCrunch](https://techcrunch.com/2026/07/08/openai-releases-new-voice-models-for-more-natural-live-conversations/)).

**Voice conversations** have gone through three generations. **Standard Voice** (September 2023) chained three models: Whisper turned speech into text, the chat model wrote an answer, and a text-to-speech model read it out. Average delays were **2.8 seconds with GPT-3.5 and 5.4 seconds with GPT-4** [Confirmed] ([OpenAI](https://openai.com/index/hello-gpt-4o/)). **Advanced Voice** used GPT-4o's native audio and could answer in as little as **232 ms (320 ms on average)** [Confirmed] ([OpenAI](https://openai.com/index/hello-gpt-4o/)); it reached all Plus and Team users in September 2024 [Reported] ([TechCrunch](https://techcrunch.com/2024/09/24/openai-rolls-out-advanced-voice-mode-with-more-voices-and-a-new-look/)). Its audio ran on **LiveKit**. A LiveKit SDK in the app streamed the microphone over **WebRTC** (the web standard for live audio and video) through LiveKit Cloud to OpenAI's voice agent, which talked to GPT-4o over a WebSocket. WebRTC was chosen because WebSockets handle lost packets badly on WiFi and mobile networks [Reported, partner announcement] ([LiveKit](https://livekit.com/blog/openai-livekit-partnership-advanced-voice-realtime-api)). The third generation, **GPT-Live** (8 July 2026), is **full-duplex**: it can listen and speak at the same time, so users can interrupt naturally [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes); [TechCrunch](https://techcrunch.com/2026/07/08/openai-releases-new-voice-models-for-more-natural-live-conversations/)). OpenAI's engineering post says GPT-Live **removes the turn detector from the audio path**, streams audio in and out of the model continuously, and hands search, reasoning and tool use to a frontier model such as GPT-5.5 on a **separate background path** while the conversation continues [Confirmed] ([OpenAI](https://openai.com/index/continuous-voice-interaction-with-gpt-live/)). The same post describes protocol work (called WARP) that cuts connection setup from **six network round trips to one** [Confirmed]. Whether GPT-Live still sends audio through LiveKit is not public.

Advanced and Standard Voice **retire on 11 December 2026**, and video and screen sharing stay on Advanced until then [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes); [OpenAI Help](https://help.openai.com/en/articles/8400625-voice-mode-faq)). Since November 2025 voice runs inside the normal chat screen, and a transcript is saved into the chat afterwards [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes); [OpenAI Help](https://help.openai.com/en/articles/8400625-voice-mode-faq)). Limits are generous but real: Plus gets **3 hours per rolling 24 hours**, and Pro at $200 is unlimited [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8400625-voice-mode-faq)). "Read Aloud", which plays any answer in a ChatGPT voice, launched in March 2024 with 5 voices and 37 languages [Reported] ([VentureBeat](https://venturebeat.com/ai/openai-adds-read-aloud-voiceover-to-chatgpt-allowing-it-to-speak-its-outputs)). The public API offers the same building blocks. The Realtime API connects over WebRTC in the browser or WebSocket on a server, uses short-lived client secrets created by your own server so the real API key never reaches the browser, and offers voice-activity detection that cancels the model's reply when the user starts talking [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/realtime); [OpenAI API reference](https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets/methods/create)). One planning note: the API's older text-to-speech models shut down on 6 January 2027, and the Whisper-era transcription models on 26 February 2027 [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/text-to-speech); [OpenAI docs](https://developers.openai.com/api/docs/guides/speech-to-text)).

## GPUs set the ceiling, but outages start in config, login and shared systems

ChatGPT was born on **Microsoft Azure** and was "multi-region, multi-cluster, and globally distributed from day one", running on NVIDIA H100 servers with eight GPUs each [Reported, Evan Morikawa, who led OpenAI's Applied engineering group through the launch] ([The Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/scaling-chatgpt)). Since 2025 it has become **multi-cloud**. On 28 October 2025 Microsoft gave up its right of first refusal on OpenAI's compute, OpenAI committed to buy $250 billion more of Azure, and products outside the API, such as ChatGPT, may now run on any cloud [Confirmed] ([OpenAI](https://openai.com/index/next-chapter-of-microsoft-openai-partnership/)). AWS capacity announced in November 2025 includes **serving ChatGPT** [Confirmed] ([About Amazon](https://www.aboutamazon.com/news/aws/aws-open-ai-workloads-compute-infrastructure)), in a deal reported at $38 billion [Reported] ([DCD](https://www.datacenterdynamics.com/en/news/openai-signs-38bn-multi-year-agreement-with-aws-for-access-to-nvidia-gb200s-and-gb300s/)). Google Cloud, CoreWeave and Oracle supply capacity too [Reported] ([Reuters via The Star](https://www.thestar.com.my/tech/tech-news/2025/06/11/exclusive-openai-taps-google-in-unprecedented-cloud-deal-despite-ai-rivalry-sources-say); [Built In](https://builtin.com/articles/openai-cloud-deals)), and in January 2026 OpenAI added **Cerebras** chips for 750 MW of "low-latency" inference [Confirmed] ([OpenAI](https://openai.com/index/cerebras-partnership/)). The shared Kubernetes platform behind ChatGPT now spans **Oracle Cloud, AWS and Azure** [Confirmed] ([OpenAI Careers](https://openai.com/careers/software-engineer-cloud-infrastructure-san-francisco/)). How much traffic each cloud carries is not public.

The real limit on serving a chat model is **GPU memory, not raw compute**. Morikawa explained that each active conversation's "KV cache" (the model's working memory of the chat so far) lives in GPU memory; if it is pushed out, the whole conversation must be processed again. In the early days, the "We are at capacity" message meant every GPU was busy because no more could be bought or rented [Reported] ([The Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/scaling-chatgpt)). The team kept GPUs balanced across the fleet rather than placed near users, because token-streaming speed mattered more than network distance [Reported]. Model inference runs in the Kubernetes "data plane" across hundreds of clusters [Confirmed] ([OpenAI Status](https://status.openai.com/incidents/ctrsv3lwd797/write-up)). In August 2025 GPT-5 added a **real-time router** that picked between a fast model and a reasoning model [Confirmed] ([OpenAI](https://openai.com/index/introducing-gpt-5/)), although OpenAI later switched that automatic choice off for paid users. OpenAI has not published its inference engine, load balancer or request scheduler.

For operations, OpenAI reportedly takes in **petabytes of logs per day** through Fluent Bit into a ClickHouse cluster of 90 shards [Reported, vendor case study with OpenAI speakers] ([ClickHouse](https://clickhouse.com/blog/why-openai-chose-clickhouse-for-petabyte-scale-observability)), and its reliability job postings ask for Prometheus and Grafana [Confirmed] ([OpenAI Careers](https://openai.com/careers/software-engineer-infrastructure-reliability/)). In September 2025 it bought the feature-flag and experimentation company **Statsig**, a tool it already used, and made Statsig's founder CTO of Applications in charge of ChatGPT engineering [Confirmed] ([OpenAI](https://openai.com/index/vijaye-raji-to-become-cto-of-applications-with-acquisition-of-statsig/)), at a reported $1.1 billion [Reported] ([TechCrunch](https://techcrunch.com/2025/09/02/openai-acquires-product-testing-startup-statsig-and-shakes-up-its-leadership-team/)).

OpenAI's public status write-ups are the richest official window into the architecture, and they tell a consistent story: GPUs rarely cause the big outages.

| Date | What broke (from OpenAI's write-ups) [Confirmed] | Lesson for a smaller app [Inferred] |
|---|---|---|
| Mar 2023 | A bug in the Redis cache client showed some users other people's chat titles ([OpenAI](https://openai.com/index/march-20-chatgpt-outage/)) | Key every cache entry by user and check ownership |
| Dec 2024 | A new telemetry service overloaded the Kubernetes control plane, and service discovery (DNS) failed for hours ([OpenAI Status](https://status.openai.com/incidents/ctrsv3lwd797/write-up)) | Roll out infrastructure changes in stages; do not let all service lookups depend on one fragile system |
| Jan 2025 | A Cosmos DB failure, then web servers crash-looped on failing health checks ([OpenAI Status](https://status.openai.com/incidents/01JMYB40J9DVR9D13RJN1W5SWV)) | Health checks must not kill servers that are merely busy |
| Jun 2025 | An automatic OS update wiped network routes on GPU servers; ChatGPT errors peaked near 35% ([OpenAI Status](https://status.openai.com/incidents/01JXCAW3K3JAE0EP56AEZ7CBG3/write-up)) | Turn off unattended updates on critical machines |
| Nov 2025 | An edge provider's config rollout broke web login; the apps and API stayed up ([OpenAI Status](https://status.openai.com/incidents/01KABE2437NJYKBFHT22SD3H92/write-up)) | The edge and anti-bot layer is a single point of failure for web login |
| Feb 2026 | A new feature-flag caching path hit an "unexpected data type"; login retries amplified the load ([OpenAI Status](https://status.openai.com/incidents/01KGJK9Q6PDB3C3VX6MPCY6106/write-up)) | Validate config types; add backoff and circuit breakers on retries |
| Jul 2026 | A config change clashed with a deployed auth service, and a deploy-system bug re-applied it ([OpenAI Status](https://status.openai.com/incidents/01KYC921K145JTR1JK7DYKGWH1/write-up)) | A blocked deployment must stay blocked |
| Sep 2026 | A feature rollout triggered repeated background checks that used up shared network connections ([OpenAI Status](https://status.openai.com/incidents/01M3Q4RK1SM4EMK445GGPG7C0N/write-up)) | Cap connection pools and watch expensive queries |

[Inferred] The pattern is clear. Most outages start with a change (a deploy, a config edit, a feature flag, an OS update) and then grow through amplification (client retries, expiring caches, shared connection pools), and login shows up again and again. Those lessons apply at any size. The GPU problems do not apply to a clone that calls a hosted model.

## The feature list keeps growing, and OpenAI retires features just as fast

**Model choice** has swung from automatic to manual. GPT-5 (August 2025) used a router, but on **14 September 2026** OpenAI retired automatic switching from Instant to Thinking for Plus and Pro users [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). Today the picker is a **five-step thinking slider** (Instant, Medium, High, Extra High, Pro). Instant through Extra High run on **GPT-6 Sol**, Pro runs on GPT-6 Pro (powered by GPT-6 Astra), and Free and Go users get Instant and "Think" on a Luna model [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/11909943-gpt-6-in-chatgpt)). OpenAI's own pages disagree on whether Free and Go use GPT-5.6 Luna or GPT-6 Luna [Confirmed, conflicting]. Automatic routing survives mainly for fallback after rate limits and for safety, such as sending distress conversations to a specific model [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)).

**Personalization and memory** are now central. Custom instructions (up to 5,000 characters since July 2026), base personalities and tone sliders live together in Settings → Personalization, and since November 2025 changes apply to existing chats too [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)), which implies they are added fresh to every request [Inferred]. Memory has two parts: **saved memories** (facts stored separately from chats) and **reference chat history** (drawing on past conversations). ChatGPT "searches for relevant context only when it is likely to improve a response", and since January 2026 any past chat used in an answer appears as a source [Confirmed] ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq); [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). In 2025, outside researchers found no search at all: a stored profile plus summaries of about 15 recent chats were simply pasted into every prompt [Reported] ([Simon Willison](https://simonwillison.net/2025/May/21/chatgpt-new-memory/); [LLMrefs](https://llmrefs.com/blog/reverse-engineering-chatgpt-memory)). [Inferred] The 2026 wording points to on-demand retrieval, so the design appears to have changed since then. One study found that **96% of memories are created by the system itself**, not by users asking it to remember [Reported] ([arXiv](https://arxiv.org/html/2602.01450)), and OpenAI has said memory can make sycophancy (telling users what they want to hear) worse [Confirmed] ([OpenAI](https://openai.com/index/expanding-on-sycophancy/)).

**Search, projects and tools** extend the basic chat. ChatGPT search (October 2024) uses a fine-tuned model that decides when to search, pulls from "third-party search providers" and news partners, and lists sources in a sidebar [Confirmed] ([OpenAI](https://openai.com/index/introducing-chatgpt-search/)). Analysts concluded that its index comes largely from **Bing** [Reported] ([Search Engine Roundtable](https://www.seroundtable.com/bing-powers-chatgpt-search-38345.html)), and OpenAI runs its own **OAI-SearchBot** crawler [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/bots)). **Projects** (December 2024) group chats with shared files, instructions and their own memory scope [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). **Apps** are built on the **Model Context Protocol (MCP)** through the Apps SDK (October 2025) [Confirmed] ([OpenAI](https://openai.com/index/introducing-apps-in-chatgpt/)). **Custom GPTs retire on 11 December 2026** and turn into "plugins" that bundle instructions (as skills), reference files and apps [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/20001519-custom-gpt-retirement-and-migration-faq)). Agent mode (July 2025) ran tasks on a virtual computer [Confirmed] ([OpenAI](https://openai.com/index/introducing-chatgpt-agent/)) and has been followed by **ChatGPT Work** (9 July 2026), a long-running agent built on Codex technology [Confirmed] ([OpenAI](https://openai.com/index/chatgpt-for-your-most-ambitious-work/)). OpenAI has also removed Canvas from GPT-5.5 models (May 2026), stopped new group chats (July 2026), begun sunsetting Pulse, and replaced Library with Space (20 November 2026) [Confirmed] ([ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)).

**Sharing, privacy and feedback** round out the product. Shared links from personal accounts are **frozen snapshots**: anyone with the link can view them, and continuing one creates a private copy in the viewer's account [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/7925741-chatgpt-shared-links-faq)). **Temporary chats** stay out of history and never create memories, but OpenAI may keep them for up to 30 days for safety [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/8914046-temporary-chat-faq)). **Thumbs up and down** are a real training signal: OpenAI said an extra reward based on this feedback helped cause the April 2025 GPT-4o sycophancy problem, which it rolled back [Confirmed] ([OpenAI](https://openai.com/index/expanding-on-sycophancy/)), and giving feedback can make the whole conversation eligible for training [Confirmed] ([OpenAI Help](https://help.openai.com/en/articles/7730893-data-controls-faq)). On safety, OpenAI publishes a **free Moderation API** that covers 13 categories for text and images [Confirmed] ([OpenAI docs](https://developers.openai.com/api/docs/guides/moderation)), but it does not publish ChatGPT's internal moderation pipeline.

## A clone needs about a dozen ordinary building blocks before anything fancy

The research splits ChatGPT's engineering into two piles [Inferred]. The first pile exists because OpenAI runs its own models for hundreds of millions of people: GPU fleets, KV-cache management, multi-cloud contracts, hundreds of Kubernetes clusters and a real-time model router. A clone that calls a hosted model API skips this pile entirely. The second pile is what any chat product needs, and it is where ChatGPT's design is worth copying. The tables below describe that second pile. The "What it requires" column lists capabilities, not products, so it can be used as a checklist when comparing tech stacks. Two choices deserve the most care because they are the hardest to change later: **storing messages as a tree**, and **the streaming event format** (including whether the answer keeps generating when the browser disconnects). The web framework, by contrast, is easier to swap: outside teardowns show OpenAI changed ChatGPT's framework twice without users noticing.

**MVP: the core chat loop**

| # | Building block | What it does | What it requires | ChatGPT reference |
|---|---|---|---|---|
| 1 | Chat screen | Composer, message list, markdown, code and math display, Stop, Copy, Regenerate, light and dark themes | A UI layer that can re-draw a growing message many times per second; markdown display that copes with half-finished text; code and math renderers that load only when needed; theme color variables; auto-scroll that pauses when the user scrolls up | React + TypeScript [Confirmed]; React Router 7, Tailwind tokens, ProseMirror, CodeMirror, KaTeX [Reported] |
| 2 | Accounts and sessions | Sign-up, login, logout, staying signed in | Email login plus at least one social login (OpenID Connect); a secure, HttpOnly session or refresh cookie; a short-lived token or session check on every API call; an ownership check on every conversation | auth.openai.com with Google, Microsoft and Apple [Confirmed]; refresh cookie plus short-lived token [Reported] |
| 3 | Streaming chat endpoint | Sends the user's message and streams the answer back | A POST endpoint that returns `text/event-stream`; a server that can hold many open connections without blocking; a client-side stream reader (the browser's EventSource cannot POST); a small event format (start with message IDs, text pieces, done, error); Stop as a client abort plus a server cancel; saving partial answers | SSE over POST with `v1` patches [Reported] |
| 4 | Model gateway | Talks to the model provider | Provider API keys kept on the server only; a model list in config; a prompt builder that walks the active branch and fits a token budget; injection of the system prompt and custom instructions; retries with backoff; friendly handling of provider rate limits and outages | Own GPUs and router [Confirmed]; a clone would call a hosted API instead [Inferred] |
| 5 | Conversation store (tree) | Saves chats so they survive reloads and support branches | A database with a conversations table and a messages table (`parent_id`, role, flexible JSON content, status), a `current_node` pointer, and indexes for "children of a message" and "a user's chats by last update" | `mapping` tree [Reported]; Postgres plus Cosmos DB [Confirmed] |
| 6 | History sidebar | Lists, opens, renames, deletes, archives and pins chats | A list endpoint sorted by last update with paging (cursor or offset); a background job that writes an auto-title using one cheap model call; per-user caching with ownership checks | 28 chats per page [Reported]; `gen_title` route [Reported] |
| 7 | Edit, regenerate and version switcher | Lets users rewrite a prompt or retry an answer, then flip between versions | The tree from block 5, UI for sibling messages, and an update to `current_node` when the user switches | Sibling branches [Reported] |
| 8 | Model picker and custom instructions | Lets users choose a model or effort level and set standing instructions | A per-user settings record; instructions added fresh on every turn (ChatGPT allows 5,000 characters) | [Confirmed] |
| 9 | Safety and abuse controls | Keeps the service safe and affordable | A moderation check on input (and on the final output); per-user and per-IP rate limits; a bot check on sign-up and on send; usage counters per user, model and time window, with fallback to a cheaper model | Sentinel and Turnstile [Reported]; layered limits and fallback models [Confirmed] |
| 10 | Feedback | Thumbs up or down and an optional comment per answer | A feedback record per message that also stores which model answered | [Confirmed] |
| 11 | Operations basics | Lets you see and control the running app | Structured logs, error tracking, and token and cost counts per request; feature flags with kill switches and safe defaults; health checks that do not restart busy servers | Statsig, ClickHouse logs and incident lessons [Confirmed / Reported] |

**Later: features to add once the core loop is solid (roughly in this order)**

| # | Building block | What it requires | ChatGPT reference |
|---|---|---|---|
| 12 | Image and file attachments | Object storage; direct uploads through short-lived signed URLs; file records (id, type, size, dimensions); type and size limits plus per-user quotas; image downscaling; text extraction and PDF page images; a vision-capable model | Upload first, then a pointer [Reported]; 20 MB per image and 20 files per message [Confirmed] |
| 13 | Web search with citations | A search tool or API; a tool-calling loop; citation data attached to parts of the answer; a Sources panel | [Confirmed] |

Can the server side hold thousands of open streaming responses cheaply and cancel them cleanly? Does the database handle flexible JSON content and "parent and children" lookups well, and can it later be split by user or conversation if writes grow? Is there a simple way to run background jobs for titles, exports, deletions and image generation? Is there object storage with signed direct uploads? ## Conclusion

The most useful surprise in this research is how unexotic ChatGPT's application layer is. The world's most-used chatbot runs on React, Python, PostgreSQL, Redis and plain server-sent events, and OpenAI has scaled those ordinary tools through discipline (read replicas, connection pooling, no big joins, cache leases, layered rate limits) rather than by inventing new ones. The truly hard engineering sits below the chat app, in GPU capacity, and in front of it, in bot defense. A clone avoids the first by renting a model and needs only a modest version of the second. That moves a clone's real risk to two early decisions, the message data model and the streaming contract, which ChatGPT has kept stable while it changed web frameworks twice and rewrote its voice server in a new language.

The second lesson is about change. OpenAI's own outages mostly start with its own config, flag and deploy changes, and its product list turns over within months: Canvas, custom GPTs, group chats and automatic model switching for paid users were all retired or cut back within about a year. A clone built on durable pieces (a message tree, a typed event stream, instructions plus files plus MCP tools, and per-user limits) can follow that churn cheaply, while one built around a specific feature cannot. Because most of what is known about chatgpt.com's internals comes from outside inspection, every [Reported] detail here is a snapshot to learn from, not a contract to copy.
